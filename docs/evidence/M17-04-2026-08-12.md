## Acceptance mapping

- Installed CUDA and XDMA candidates now expose borrowed
  `hal_v2_registration(std::string_view) noexcept` accessors with HAL core v2,
  memory/topology v1, and command/timeline v1 tables. Checked path selection
  prevents simultaneous initialized use through device ABI v1 and native v2;
  the existing `api()` tables remain device ABI v1.
- Both driver records preserve their complete version-1 positional prefix,
  default to version 1, and add exact version-2 tails. V1 accepts only its
  frozen size and zero tail; v2 requires the exact full size, required
  callbacks, and zero reserved fields.
- CUDA v2 adds `graph_launch`; the production adapter maps it to
  `cuGraphLaunch`. The backend stores at most 16 caller-owned pre-instantiated
  graph executables and eight copied name/access bindings per graph. IDs are
  unique and in `[1, 65535]`; dispatch uses `0x43470000 | graph_id`, zero
  payload, exact ordered bindings, and no native pointer in identity.
- CUDA discovery reports host or pinned-host staged memory according to the
  configured registration behavior, explicit copy-to/from-device obligations,
  copied names/tokens, the existing mirror or pre-bound address rules, a
  host/device topology, and host-monotonic completion timestamps. It makes no
  physical pinning, device-memory, coherency, topology, or clock claim.
- Native CUDA batches validate the complete frame before driver entry, execute
  declared copies, kernels, and graphs on `streams[0]`, and record one
  precreated event after enqueue. Unknown IDs, foreign/legacy buffers, binding
  mismatches, malformed commands, launch/event errors, timeout, stop, reset,
  context loss, and shutdown retain the tested quarantine/drain behavior.
- XDMA v2 adds `control_read32`, `control_write32`, `wait_user_event`, and
  idempotent `request_stop`. Exact opcodes are `0x58480000 | offset/4`,
  `0x58490000 | offset/4`, and `0x584A0000 | event_index`; aperture validation
  is aligned, nonzero when enabled, and at most 262144 bytes, while event count
  is at most 16. Reads/events use exactly one writable four-byte borrowed-host
  result; writes use one four-byte little-endian payload.
- Native XDMA validates opcode families, high bits, ranges, access, payload,
  reserved data, and callback availability before fixed-worker driver entry.
  H2C/C2H remain available through their stable opcodes. Finite remaining
  timeout, queued/running cancellation, stop wakeup, recovery, buffer
  quarantine, and two-instance isolation are covered by the portable fake.
- The Linux adapter copies H2C, C2H, optional user-BAR, and up to 16 event paths;
  opens with close-on-exec, opens event nodes nonblocking, uses an eventfd stop
  wakeup, retries EINTR, rejects short four-byte I/O, and retains descriptors
  through bounded reset/shutdown ownership. The fixture used temporary regular
  files only and did not access hardware.
- Independent risk review repaired three vendor-path concurrency/capability
  defects. CUDA core and batch pollers now acquire the shared slot state before
  reading its batch discriminator. XDMA queued cancellation now publishes a
  canceled completion without issuing a driver-wide stop that could interrupt
  unrelated running work; running event cancellation alone uses the stop
  wakeup, which the Linux adapter consumes and rearms. Linux XDMA now advertises
  control callbacks only for a configured user-BAR path and event/stop callbacks
  only for configured event paths. Native XDMA batch submissions, completions,
  cancellations, queue rejection, and outstanding work now enter the existing
  health counters.
- All Graph, queue, batch, event, worker, descriptor, and stop storage is fixed
  at construction/initialization and remains backend-private. Runtime-owned
  `device_control_bytes`, six-row MemoryPlan accounting, thread-role inventory,
  and generic submission/service lanes are unchanged.
- Documentation, governance, permanent future-safe contract checks, release
  source digests, default/opt-in consumers, permanent CTest gates, TSan filter,
  and hosted compile-only CUDA/XDMA adapter job were updated. M17 and CAP-M17
  remain incomplete; combined execution and qualification remain deferred.
