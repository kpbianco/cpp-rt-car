## Implemented boundary

M16-03 adds a copied, configuring-only `RateExecutionPolicy`. Its positive
per-step record cap is the sole opt-in switch. Without it, explicit M16-01 and
M16-02 plans retain complete-graph once-per-frame execution and legacy artifact
behavior. Late-action and catch-up fields are appended to public aggregates;
package tests retain their pre-M16-03 positional prefixes.

Active finalization accepts only mandatory CPU D0 plans with positive budget
and deadline, deadline no greater than period, same-domain ordinary graph
dependencies, and bounded valid late actions. It rejects active D1, device
records, optional work, cross-domain ordinary dependencies, zero or ambiguous
inputs, skip producers, and active schema-1 input-log/replay. One complete
supercycle is admitted in exact reference order on a conservative serialized
lane using checked `max(previous_finish, release) + budget` arithmetic.

Active host steps map logical epoch zero to the first supplied nominal release.
Every later nominal timestamp must equal the checked epoch plus contiguous
logical cursor. Dispatch covers exactly `[cursor, cursor + delta)`, repeats the
immutable reference vector with checked supercycle arithmetic, preserves
equal-time domain/phase/substep order, and uses the existing selected-phase
executor boundary. `run_periodic()` supplies its existing absolute release;
host-driven steps do not sleep.

Each domain release receives one pre-dispatch deadline decision. `skip` and
`hold` aggregate bounded omitted prefixes; bounded catch-up stops at its
positive per-step cap; `degrade` increments the existing capped degradation
level before callbacks; `fail` executes no record and gates later steps and
checkpoint restore until checked stop. The global record cap is checked before
each selected group. A partially attempted multi-record release counts every
unattempted record as rejected before cancelling later work. Functional result
tails report exact due, executed, on-time, late, caught-up, skipped, held,
degraded, rejected, stale, failed, and first-failure fields without changing
observability schemas.

Active callbacks receive an additive nullable `RateReleaseView`. Every producer
record must publish one exact-size payload per outgoing channel. Publication is
complete before store visibility, duplicate or missing publication fails the
release, and the publication-claim transition cannot overwrite a concurrent
duplicate marker. Compiled consumer reads copy only the exact initial,
produced, or explicitly held generation. Results preserve provenance,
generation, age, held, freshness, ownership, size, not-ready, and stale
distinctions. Store retirement remains bounded and finite generation
exhaustion fails closed.

One reserved generic checkpoint record persists the logical cursor, epoch,
fault coordinates, degradation level, channel generations/aliases/provenance,
and canonical committed bytes. Restore validates inner semantic relations in
addition to outer artifact checksums before rebuilding stores and application
state. Legacy/reference-only schema-1 bytes and codecs are unchanged.

## Independent system-risk review and repairs

The uncommitted batch received an independent agent review of the full diff,
public/package boundaries, architecture and safety contracts, active runtime,
executor, exact-generation stores, checkpoint state, tests, release ledger,
and claim language. Two material in-scope findings were repaired:

1. A callback failure partway through a multi-record domain release subtracted
   the whole group from the rejected count. The runtime now snapshots the
   executed count before the group and rejects exactly the due records that
   were neither previously settled nor actually attempted. The permanent
   `CallbackFailureRejectsEveryUnattemptedSubstep` test proves a three-substep
   release executes one failing callback, rejects two records, cancels the
   remaining substeps, and reports the exact first failure.
2. Two concurrent publication attempts could race so the successful writer's
   final store replaced the duplicate marker. The writer now completes the
   claim with a `writing -> complete` compare-exchange; an observed duplicate
   marker is never overwritten, so the release fails closed and staged bytes
   are not committed.

No stable ABI, schema, package inventory, support claim, hardware path, or
forbidden path was changed by these repairs.
