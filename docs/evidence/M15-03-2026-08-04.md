## Evidence classification and claim boundary

This record contains static review, deterministic local build/test, injected
provider, mock-device, package/consumer, and one named-host Linux functional
observation. It is not physical accelerator, HIL, field, latency, thermal,
endurance, RT1, RT2, signing, release, staging, deployment, production, or
device/DMA-pinning evidence. No commit, push, pull request, release, deployment,
secret, or repository-setting operation was performed.

## Implementation result

M15-03 adds one copied, exact-size/versioned C++ `MemoryProvider` table with
bounded acquire, apply, observe, rollback, and nonthrowing release callbacks.
The runtime borrows its `user_data` through checked cleanup and rejects runtime
operational reentry while a provider callback is active.

Exactly the active phase-scratch, task-scratch, and trace-storage regions are
owned by a per-runtime resident-region transaction. Finalization acquires them
in that order, validates complete allocation extents and constructs dependent
objects only after acquisition succeeds. Startup applies and independently
observes policy before the M15-02 thread gate. Failure and checked stop roll
back effects and release provider tokens in reverse order. Executor task
scratch and telemetry storage now accept nonowning resident spans; trace atomics
are placement-constructed and destroyed before provider release.
Live tokens and allocation extents are checked across all runtime instances,
preventing a shared provider from aliasing ownership or backing storage.

The no-provider default retains aligned allocation. Linux page-policy requests
use process-local `mmap`, base-page rounding, inaccessible guards,
`MAP_HUGETLB` only for explicit huge-page attempts, explicit fallback,
caller/prefault page touch, `mlock` application, and `mincore` residency
observation. Locking-only storage is independently
page-backed so page-granular lock/unlock cannot affect another runtime.
`mlock` is never reported as independent lock readback or as provider/device/
DMA pinning. Native physical NUMA placement is not independently observed, so
strict runtime-provider requests are rejected and best effort falls back;
injected-provider NUMA success requires advertised capability and independent
observation.

## Independent risk-review findings and repairs

- **High:** a failed provider acquire that returned a process-live token could
  bypass the success-path registry check and release another runtime's token
  during failure cleanup. Provisional failure tokens/extents are now claimed
  atomically against the process-live registry before cleanup; aliases are not
  adopted or released. The cross-runtime regression test proves the first
  runtime remains usable and its token is released only by its own checked stop.
- **High:** duplicate live provider tokens were adopted twice and therefore
  released twice on rejection. Duplicate detection now precedes ownership
  adoption within one runtime; a process-live token/extent registry extends the
  check across runtimes. A malformed second alias is not released through the
  second runtime because doing so could invalidate its existing owner, while a
  distinct overlapping token is released by the rejecting transaction.
- **High:** provider callbacks could reenter operational APIs not covered by
  the initial configuration gate. In particular, stop-time release ran after
  executor destruction while state was still `running`, so reentrant `step()`
  could dereference a null executor. All status-returning operational APIs now
  reject while a provider callback is active, with a release-callback
  regression test covering the dangerous window. Observation accessors now
  return bounded empty/default values during callback reentry as well.
- **High:** rollback errors were recorded but checked stop still released
  provider tokens and returned success. Failed provider/native rollback now
  remains pending and retryable; start/stop fail closed, execution stays
  blocked, and token release occurs only after a checked rollback retry
  succeeds.
- **High:** M15-03 fields were inserted into the middle of the public
  `MemoryPolicyReport` aggregate, so valid 1.x positional initialization could
  stop compiling or bind values to different members. The pre-M15-03 member
  prefix is restored exactly, all new fields are appended, and a compile/run
  compatibility gate initializes and verifies the legacy prefix.
- **Medium:** native `mbind` policy readback was treated as independent NUMA
  placement verification even though the selected pages were already touched
  during finalization. Native strict NUMA now fails before acquisition and best
  effort resolves to default placement; injected providers remain eligible only
  with NUMA-binding and independent-observation capabilities.
- **Medium:** guard metadata was trusted without proving the claimed leading
  and trailing guards were contained in the provider allocation extent. The
  validator now checks both sides and rejects contradictory huge-page outcomes,
  zero or non-power-of-two page sizes, and malformed base-page rounding before
  object construction. Behavioral tests prove transactional rejection, absent
  partial reports, and exact cleanup.
- **Medium:** strict no-fallback policy accepted a provider that silently
  reported huge-page fallback. Allocation validation now rejects that outcome,
  and native Linux explicitly requests 2 MiB hugetlb pages before any allowed
  base-page fallback.
- **Medium:** trace requests reported zero resolved alignment even though the
  actual storage requires 64-byte alignment. The resolved row and captured
  provider request now report and test the same 64-byte requirement.
- **Medium:** active runtime/external stack inventory rows with zero accounted
  bytes were mislabeled inactive. Activity now follows stable cardinality and
  logical presence while those rows remain deliberately excluded/deferred.
- **Medium:** aligned-new locking storage could share an OS page with another
  runtime, making `munlock` page-granularly affect unrelated memory. Native
  locking-only requests now use separate anonymous page-backed mappings; the
  two-runtime test exercises both lock attempts and confirms truthful zero
  verified-locked/pinned reporting.
- **Coverage:** focused gates now include failed-acquire cross-runtime token
  isolation, the legacy report aggregate prefix, truthful native NUMA fallback,
  provider-backed nested and host-adapter scratch, periodic/watchdog trace loss,
  CPU/device no-allocation frames,
  inaccessible native guards, failed-start destruction, and executor,
  watchdog, device-service, and M14.1 cleanup rollback/recovery ordering.

- Additive C++ provider API and memory-policy report fields.
- Per-runtime resident-region transaction and external phase/task/trace backing.
- Process-live provider token/extent registry and isolated native locking maps.
- Executor and telemetry object construction/destruction over resident spans.
- Linux native selected-region allocation/policy implementation.
- Focused tests, TSan filter, permanent docs/release checks, digest ledger,
  governance, product/architecture/policy documentation, and retained evidence.

- Release 1.2.1, Apache-2.0, default SDK targets/headers, compatibility aliases,

- No ordinary heap allocation, hidden threads, file I/O, blocking mutexes,
  unbounded waits, or spill execution was added to steady-state declared lanes.
- Runtime-instance isolation and borrowed/application/backend ownership.
- CUDA/XDMA candidates and experimental scheduler/fiber/plugin surfaces remain
  untouched and outside `rtfw::runtime`.

## Residual risks and rollback

- Provider callbacks are trusted host control-path code; independent provider
  observations and capability claims require integrator review.
- A provider that permanently fails rollback prevents checked stop from
  releasing its tokens; C++ destruction remains only a best-effort fallback.
- Kernel/page/NUMA/lock behavior is host-specific. This host had no configured
  hugetlb pages and no effective capabilities. The `mlock`/`munlock` path was
  exercised but Linux supplied no independent lock readback; explicit huge
  allocation and native NUMA binding remain unobserved; native strict NUMA is
  deliberately unavailable without independent physical-placement observation.
- Provider-backed trace is intentionally unavailable after checked stop because
  its storage has been released. Default trace retention remains compatible.
- M15-04 must close fragmented control storage, stack residency, exact
  external/backend accounting, and total byte closure before broader memory
  residency claims.

Rollback is one coherent revert of the provider API, resident-region/native
implementation, executor/telemetry span integration, tests/CI, documentation,
governance, checkers, digest ledger, and this evidence. Before removing a live
integration, call checked `stop()` so lanes quiesce, native effects reverse,
and provider tokens release. There is no migration, persistent machine change,
support promotion, release, or deployment to undo.
