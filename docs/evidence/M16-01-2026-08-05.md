## Implemented model and boundary

The installed C++ header inventory now exposes an additive, instance-owned rate API. Bounds are 64 domains, 63-character NUL-terminated identifier payloads, 64 substeps per domain, and 65,536 reference-release entries. Registration copies the identifier and the integral-nanosecond period, substep count, relative deadline, non-binding budget/WCET estimate, criticality, and optionality. CPU and device phases use existing stable phase handles and bind exactly once to a distinct rate-domain handle.

Finalization first compiles the existing dependency/resource graph and then compiles the rate model transactionally. It validates the compiled phase permutation, every owner/kind/index, nonempty domain ownership, exact one-phase ownership, unique restricted names, enums, positive periods/substeps, and all bounds. It uses integer `gcd`, checked `lcm`, multiplication, addition, and release counting only. The immutable interval is `[0, lcm(periods))`. Failure leaves the runtime configuring, publishes no partial plan, and permits metadata replacement and retry before any provider, native-policy, thread, device-ownership, or callback action.

Inspection copies records in deterministic order. Equal timestamps sort by domain registration order, compiled phase order, then substep ordinal. The plan does not depend on floating point, sleeps, pointer order, unordered iteration, wall time, or scheduling. Construction storage is acquired only during configuration/finalization; inspection does not mutate or resize it.

This remains reference-only. `step` and `run_periodic` still execute the complete graph once per host frame. No release gates, repeats, skips, catches up, holds, degrades, sheds, admits, or changes sample freshness or telemetry.
