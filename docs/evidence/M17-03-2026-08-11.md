## Public definitions and compatibility

The installed `rt/device.hpp` remains the only device C++ header. The optional
command/timeline extension has version 1 beside unchanged HAL core version 2
and memory/topology extension version 1. `HalV2BackendRegistration` appends one
borrowed `command_timeline` pointer after the exact M17-02 positional prefix
`{name, api, memory_topology}`; Runtime validates and copies the table before
publication.

Fixed public limits are 16 commands per batch, eight wait points, eight signal
points, 16 timelines per backend, the existing 128-byte inline payload, and
eight buffer references per command. Command kinds have fixed values:
dispatch 1, copy 2, and memory synchronization 3. Memory operations name only
copy-to-device, copy-from-device, flush, and invalidate.

## Ownership, lanes, identity, and accounting

For each opted-in backend, finalization allocates
`device_outstanding_capacity` batch slots and one submission-lane control,
startup result, context, and native thread. A single shared bounded completion
scratch array uses `device_completion_batch` records. Timeline state contains
the copied stable name, backend index, initial value, atomic last-accepted
value, and atomic completed value. The tested fixture reports one opted-in
backend, one timeline, and two queue slots.

The checked device-control estimate and logical extent both include:

```text
batch_backend_count * sizeof(CommandTimelineExtensionState)
+ timeline_count * sizeof(TimelineState)
+ backend_count * sizeof(BatchBackendState)
+ batch_backend_count * device_outstanding_capacity * sizeof(BatchSlot)
+ batch_backend_count * sizeof(NativeThread)
+ batch_backend_count * sizeof(ThreadStartupResult)
+ batch_backend_count * sizeof(SubmissionLaneContext)
+ (batch_backend_count != 0 ? device_completion_batch : 0)
    * sizeof(HalV2BatchCompletion)
```

Checked multiplication/addition rejects an unrepresentable plan before
provider acquisition or thread/backend startup. Backend-declared private
command control storage remains informational and excluded. Submission stacks
are counted once under `thread_role_device_submission`; no seventh MemoryPlan
row or fourth provider region was added.

The provider executes on an executor worker, returns a caller-borrowed batch,
and performs no backend call. Runtime validates and copies it before a release
publication to the matching lane. The lane owns the potentially blocking
submit callback. The existing service lane alone performs bounded nonblocking
completion polls, validates a whole completion record, advances all declared
timelines, and releases the graph token. A validated completion observed while
submit is still returning enters an explicit completion-ready state and wakes
the service lane; locally synthesized failures carry no timeline-publication
authority. Stop uses explicit free/reserved/queued/submitting/submitted/early-
ready/completion-ready/owned states, closes admission, requests stop, cancels,
wakes, reverse-joins submission lanes, then completes existing reverse service,
memory, and backend cleanup.
