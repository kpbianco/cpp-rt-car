## Engine API and ownership review

- The only exact-version internal surface is the D-009 exception around
  `LowLevelTasks::FTask`, `TryLaunch`, `TryExpedite`, task completion, and the
  bounded test rejection seam. No Unreal Private header is included.
- All memory, time, module, and automation use is through public Core APIs:
  `FMemory`, `FPlatformTime`, ordinary module interfaces, and automation
  interfaces.
- Runtime-module load is passive: it creates no Runtime, world delegate,
  worker, process-global Runtime registry, or unload protocol.
- Job slots, copied jobs, task nodes, generations, and counters are
  instance-owned and pre-reserved. Submit/help are bounded and nonblocking;
  accepted work executes once, stale/generation-wrap cases fail closed, and a
  task node is not reused until scheduler completion is observed.
- Logical worker indexes are RTFW adapter indexes, not claims about Unreal
  thread identity, affinity, priority, stack, or completion order.
- The memory adapter owns only the three existing Runtime regions, validates
  size/alignment, observes allocator extent independently, rolls back in
  reverse order, retains unresolved ownership for retry, and releases each
  token once. Residency, locking, pinning, NUMA, guard, huge-page, prefault,
  and physical-commitment fields remain explicitly unsupported.
- The clock uses checked monotonic conversion, clamps concurrent observations
  to nondecreasing nanoseconds, implements no engine-owned sleep, and supports
  host-driven `step()` only. Frame delta stays distinct from the optional
  clock-domain deadline and nominal release.
- Stable C ABI v8, device ABI v1, extension ABI v1, Runtime status values,
  schemas, SONAME 8, release 1.2.1, support matrices, and Apache-2.0 remain
  unchanged.
