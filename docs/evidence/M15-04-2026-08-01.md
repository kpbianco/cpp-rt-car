## Exact-once equations and semantics

The existing budget equation remains:

```text
planned_bytes =
    runtime_control_bytes +
    executor_control_bytes +
    device_control_bytes +
    phase_scratch_total_bytes +
    task_scratch_total_bytes +
    trace_storage_bytes
```

The new live accounting equation is:

```text
runtime_live_committed_bytes =
    runtime_nonprovider_accounted_bytes +
    runtime_persistent_provider_committed_bytes +
    runtime_stack_committed_bytes
```

- Non-provider bytes are the existing logical runtime/executor/device control
  aggregates; they are not shadow-allocated or described as allocator/RSS
  measurements.
- Persistent provider bytes replace the phase/task/trace requested contribution
  with the provider's commitment, including rounding, padding, and guards.
- Stack bytes include only live runtime-owned custom stacks. Default host/OS
  stacks remain zero because the runtime cannot inspect them.
- Host and backend totals describe unique logical registrations. Aliasing one
  host span into two ownership contracts contributes twice and is not presented
  as physical-RSS deduplication.
- Resident, locked, pinned, and fallback byte totals use usable reported
  payload. Resident/lock/pin totals require a live commitment. Resolution,
  allocation, and huge-page fallback collapse to one contribution per region.
- Zero-byte regions retain their identity/count while contributing zero bytes.

## Lifecycle transitions

1. Finalization builds the stable inventory and resolves policy as before.
2. Phase, task, and trace providers allocate and verify in order.
3. Before publishing the finalized runtime, reconciliation checks unique keys,
   ownership/scope, rollback state, provider commitment bounds, every sum, the
   six-key plan, and informational closure. Failure releases trace/task/phase in
   reverse order.
4. Startup creates requested stacks and holds every lane at the existing atomic
   policy barrier.
5. Before barrier commit, reconciliation includes live stack commitments. An
   overflow or closure error aborts the barrier, reverses device startup, joins
   executor/watchdog/device lanes, and then releases stack storage.
6. Successful start exposes live stack commitment while callbacks run. Stop
   joins lanes and reduces the stack commitment to zero. Persistent provider
   regions remain live until runtime destruction.
7. Rolled-back reports may retain failure/fallback diagnostics but cannot retain
   nonzero committed bytes. Later retry and separate runtimes recompute only
   their own current reports.

## Changed and preserved invariants

Changed:

- The C++ source API exposes a checked, allocation-free accounting snapshot over
  current memory policy reports.
- Finalization and startup validate exact-once accounting closure before
  publishing finalized state or releasing callbacks.
- Provider commitment must be at least its usable payload, and aggregate
  commitment overflow fails closed with reverse cleanup.
- Live custom-stack totals appear only between successful creation and release.

Preserved:

- stable C ABI v8, exact 70-symbol allowlist/fingerprint, SONAME 8, device ABI
  v1, runtime-config schema 7, package components/targets, installed-header
  inventory, compatibility aliases, Apache-2.0, and release/support claims;
- the six-term M4 `planned_bytes` equation and requested-byte budget semantics;
- runtime/executor/device control allocation topology and provider ownership;
- external registered state, device buffers, backend storage, host stacks, and
  vendor stacks remain verify-only and are never runtime-owned or mutated;
- callbacks and steady-state RT lanes add no provider lookup, allocation, file
  I/O, hidden thread creation, blocking mutex, unbounded wait, or spill path;
- deterministic graph/replay behavior and per-runtime isolation remain intact.

## Rollback and residual risks

Batch rollback is a source revert to the M15-03 baseline. There is no data or
ABI migration.

Residual risks:

- The snapshot trusts provider-reported commitment and state after enforcing
  payload bounds and checked totals; it cannot independently prove physical
  mapping, residency, lock, pin, huge-page, or NUMA truth for a custom provider.
- Non-provider control totals remain the contracted logical allocation topology,
  not allocator metadata or process RSS. External aliases are intentionally
  counted per registration contract, not deduplicated physical pages.
- Duplicate-key validation is allocation-free and bounded but quadratic in the
  report count. Snapshot inspection is a non-RT host operation; it is not added
  to callback or steady-state submission paths.
- Runtime lifecycle/introspection methods retain the existing host-side
  synchronization contract; callers must not race snapshot reads with start,
  stop, or destruction.
- The local focused sanitizers used Debug to avoid a GCC 15 RelWithDebInfo
  optimizer stall. The complete required sanitizer/build-mode matrix remains a
  GitHub CI obligation.
- TSan's supplied-stack warning means the small custom-stack tests are lifecycle
  evidence, not an instrumentation-stack sizing recommendation.
