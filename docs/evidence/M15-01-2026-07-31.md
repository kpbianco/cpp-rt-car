## Changed and preserved invariants

Changed:

- The C++ source API can copy an independent CPU/memory policy request during
  configuration and expose immutable reports after finalization.
- Finalization retains policy requests/reports and includes their storage in
  `runtime_control_bytes`; default `planned_bytes` therefore reflects this new
  inspectable runtime control state.
- Every current logical thread/region registration has a stable role/category
  identity and unique accounting key. The first six memory keys exactly
  partition the runtime plan; excluded registrations remain informational.

Preserved:

- C ABI v8, 70-symbol allowlist, fingerprint, SONAME 8, and device ABI v1;
- runtime-config schema 7, profile parsing, package targets/header inventory,
  compatibility aliases, license, release/support claim boundary;
- current worker/watchdog/device/XDMA thread construction and wait behavior;
- current allocation providers, stack ownership, locking, pinning, NUMA,
  huge-page, first-touch, residency, and preflight behavior;
- no policy lookup, allocation, mutation, or new thread on callback and
  steady-state paths;
- multiple runtime instances retain independent request/report storage.

## Residual risks

- The public C++ shape is additive but intentionally broad; maintainer review
  is still required before merge because later native providers must populate
  it without incompatible redesign.
- Device ABI v1 does not expose backend worker count. XDMA/accelerator lanes
  are therefore explicit host declarations and are not inferred from backend
  identifiers.
- Excluded entries identify logical ownership registrations, not deduplicated
  physical RSS. One aliased host span can legitimately have separate state and
  device-buffer keys; the excluded byte sum is not runtime-plan accounting.
- Native and cross-platform behavior remains untested until later M15 batches.
- GitHub compiler/OS, ThreadSanitizer, determinism exchange, installed-package,
  and compatibility jobs remain authoritative and have not run on this branch.

## Validation not performed and claim boundary

No affinity, priority, scheduler, NUMA, custom stack, guard-page, prefault,
`mlock`, pinning, huge-page, first-touch, residency, native apply/verify, or
rollback operation was performed. No CUDA, XDMA, combined hardware,
privileged-host, thermal, endurance, RT1, or RT2 validation was performed.

This evidence establishes static, unit, simulated, package-contract, and local
portable RT0 behavior only. Policy configuration and passing portable tests do
not qualify a deployment or establish a latency bound.
