## Claim boundary

This batch establishes portable RT0 software behavior for copied CPU-to-device
and device-to-CPU sample-and-hold payloads over admitted M21-01/M21-02 device
releases and pre-registered host-visible coherent buffers. It does not
establish sampled-I/O clock, trigger, calibration, safe-output, overrun or
underrun semantics; checkpoint/replay closure for device-produced metadata;
physical CUDA, XDMA, DAC, DAQ, CAN, IIO, ECU, or HIL behavior; controlled
performance, latency, RT1, RT2, Unreal integration, signing, publication,
release, deployment, or production readiness. M21 and CAP-M21 remain
incomplete.

## Changed files and preserved invariants

The batch changes only the synchronized governance records; the public C++
runtime header; cross-rate compiler/store integration; rate-dispatch indexes;
device terminal-slot ownership; host Runtime execution; focused CMake/tests;
the approved component documentation; release digest ledger; and this evidence
record. No forbidden ABI, schema, support-matrix, vendor backend, sample,
experimental SimCore, version, license, signing, qualification, or prior
evidence path is changed.

Ordinary command batches still require their exact declaration. Channel-free
active device phases retain M21-02 behavior and storage shape. CPU-only
cross-rate plans do not create device endpoint indexes. Runtime owns only
fixed control/store bytes; application-registered device-buffer envelopes
remain borrowed and excluded from `planned_bytes`.

The focused CPU-to-device fixture first rejects a two-byte stride before any
provider call, corrects the copied registration, then admits two same-release
substeps and proves the provider sees the exact CPU-produced bytes twice while
the backend retains both completions and receives disjoint four-byte
Runtime-selected subranges at offsets 0 and 4. The focused device-to-CPU fixture writes output at
submission but withholds terminal completion; its dependent CPU cannot run or
observe the bytes until the exact completion is released, after which payload,
generation 2, release sequence 0, substep 0, successful status, timestamp
domain 201, timestamp 77, zero age, produced provenance, fresh state, and
non-held state agree.

The broader set includes M16 selection/wrap/tie/freshness/store/SPSC and
two-Runtime isolation behavior, M21 admission/overlap/timeout/quarantine,
ordinary M17 batch/timeline/device behavior, heterogeneous-memory access and
identity, exact memory reconciliation, periodic execution, no-allocation, and
checkpoint/replay regressions. The sanitized subset specifically covers both
new payload directions and independent active device overlap; the broader set
retains the existing SPSC snapshot publication/copy concurrency tests.

The batch contract names `tests/test_multiple_instances.cpp` and
`tests/test_determinism.cpp`, but those standalone files do not exist at the
approved target baseline; the applicable coverage resides in the existing
host/device/cross-rate suites and `tests/test_determinism_replay.cpp`. This is
an inventory mismatch in the validation command, not evidence that an absent
test passed. Hosted CI and human review remain authoritative for the declared
full regression and artifact-exchange gates.

The first hosted all-branches Scaling Smoke run configured successfully and
then failed the supported runtime build because GCC's project-wide
`-Wshadow -Werror` rejected the new local device-output variable `state` as a
shadow of `Runtime::Impl::state`. The local was renamed `channel_state`; strict
local syntax verification was repeated with `-Wshadow`, and the release digest
ledger and contract gate were refreshed before requesting a replacement run.
This was a portability-warning defect, not a runtime-test or scaling-threshold
failure.

## Residual risks and required external gates

- Portable evidence uses a deterministic fake HAL backend and coherent host
  storage. It is not physical-device or electrical evidence.
- The endpoint failure matrix and payload-specific failure-preservation cases
  receive inherited component coverage plus control-flow review locally; the
  full compiler/sanitizer/determinism matrix and human ownership review remain
  required before merge.
- Device completion metadata is deliberately not serialized into schema-1
  checkpoints or replay inputs. Restoring a device-produced channel state that
  lacks the required metadata fails closed; M21-05 owns schema-neutral replay
  closure.
- No controlled performance or tail-latency claim is made. M23 owns retained
  subsystem benchmarking and regression thresholds.

Before merge, the exact published commit must pass hosted GCC/Clang/MSVC,
ASan/UBSan/TSan, determinism and artifact exchange, installed/relocated
package consumers, C ABI/SONAME, documentation, dependency, portable
assurance, autotune, scaling, and prior-regression jobs. Human review must
confirm endpoint derivation, coherency and range admission, disjoint in-flight
ownership, terminal-success publication ordering, additive compatibility,
bounded/no-allocation behavior, and this claim boundary.

## Rollback

Revert the synchronized M21-03 governance, additive selectors/read metadata,
compiled endpoint and phase/channel indexes, Runtime-owned materialization and
terminal capture, device-slot retention, accounting, tests, documentation,
release digests, and this record as one batch. This restores the M21-02 rule
that active device dispatch/completion is supported but every cross-rate
device endpoint is rejected, while preserving CPU-to-CPU channels and ordinary
device execution.
