## Implemented boundary

The existing installed C++ headers now expose instance-owned cross-rate channel
handles, copied fixed-payload registrations, compiled channel/selection
records, and fixed-copy inspectors. A channel connects one CPU producer to one
CPU consumer in a different explicit M16-01 domain. Names, endpoints, mode,
payload, exact copied initial bytes, inclusive maximum age, duplicates,
ownership, bindings, and all per-channel/aggregate capacities are validated.
Device endpoints are rejected.

Finalization produces two records per consumer reference release. The first
horizon chooses copied initial bytes until a producer precedes the consumer in
the existing total reference order. The repeating horizon uses a real
prior-supercycle source with cycle offset `-1` where necessary. Records retain
consumer/source indexes, release sequence and substep, exact integer age,
initial/produced provenance, held state, and fresh/stale state. Zero maximum age
accepts only age zero; `UINT64_MAX` is unbounded. Stale remains metadata.

Each compiled channel owns one preallocated two-slot SPSC `SnapshotStore`.
Each slot uses one lock-free packed `atomic<uint64_t>` with
free/writing/published/reading states and generation bits. Producer claim is a
single acquire/release CAS, payload copy occurs while non-visible, and complete
publication is a release store. Consumer acquire-load/CAS claims only the exact
published generation, copies while the producer cannot own the slot, then
release-stores published (retain) or free (retire). There is no search, spin,
block, allocation, fallback, overwrite of a retained generation, or newer
generation substitution. Results distinguish capacity, not-ready, stale, and
malformed input. The primitive is not invoked by `step()` or `run_periodic()`.
