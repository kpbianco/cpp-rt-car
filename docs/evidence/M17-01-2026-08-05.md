## Device ABI v1 compatibility map

| v1 input or operation | HAL v2 representation and behavior |
| --- | --- |
| `rtfw_device_capabilities` | Preserves backend ID, in-flight count, registered-buffer count and bytes, inline/reference capacities, cancel/reset support, deterministic-mock declaration, and reported control bytes. No v2-only capability is invented. |
| `rtfw_device_init_config` / `initialize` | Preserves requested in-flight and registered-buffer counts. A failed or exceptional call retains uncertain initialization ownership for checked shutdown. |
| `rtfw_device_buffer_registration` / `register_buffer` | Preserves name, borrowed pointer, bytes, and flags. A nonzero token is published to the manager even when the callback returns failure or throws, so rollback retains possible ownership. |
| `unregister_buffer` | Preserves the native token and clears manager ownership only after success. Failed cleanup remains retryable. |
| `rtfw_device_submission` / `submit` | Preserves runtime ID, frame, timeout, opcode, flags, full inline payload, reference count, tokens, access, offsets, and byte ranges. Exactly one v1 call is made. |
| `poll` / `rtfw_device_completion` | Uses fixed scratch prepared before start; validates the complete returned batch before copying ID, status, timestamp, and value into HAL v2 outputs. Invalid, partial, duplicate, unmatched, exceptional, or over-capacity results publish nothing. |
| `cancel` | Preserves the submission ID and status, including `UNSUPPORTED`; no retry or success promotion occurs. |
| `get_health` | Preserves state, last status, generation, submissions, completions, queue rejections, timeouts, errors, losses, cancellations, resets, and outstanding count. Malformed output is not published. |
| `reset` | Preserves the status and existing no-outstanding-work gate. |
| `shutdown` | Preserves the status and reverse cleanup order. Ownership is cleared only on successful shutdown or the existing certain no-owner initialization-failure case. |

Status values map one for one from v1 to HAL v2 for `OK`,
`INVALID_ARGUMENT`, `INVALID_STATE`, `QUEUE_FULL`, `TIMEOUT`, `ERROR`, `LOST`,
`CANCELED`, `UNSUPPORTED`, `RESOURCE_EXHAUSTED`, `INTERNAL_ERROR`, and
`RESET_REQUIRED`. Unknown v1 values and callback exceptions become HAL v2
`INTERNAL_ERROR`; existing Runtime status meanings are then used. In
particular, `UNSUPPORTED` remains a failure and is never promoted to success.

## Ownership, causal, and accounting evidence

- The adapter copies the complete v1 table at configuring time and exposes a
  table whose borrowed `instance` points to an individually allocated adapter.
  `device_v1_adapters` owns that object until after the device manager is
  destroyed.
- Finalization checks the full plan before provider, native-policy, thread, or
  backend side effects and prepares each adapter's completion scratch before
  start. Allocation/capacity failure leaves the Runtime configuring and
  correctable.
- `device_control_bytes` adds exactly one
  `sizeof(DeviceV1CompatibilityAdapter)` and one bounded
  `device_completion_batch * sizeof(rtfw_device_completion)` region per adapted
  backend. The same storage appears once in the logical device extent ledger.
- The six-row planned-byte equation remains runtime control + executor control
  + device control + phase scratch + task scratch + trace storage. The M17
  exact-delta test and permanent M15 closure/rollback gates pass.
- The service lane validates an entire completion batch, including duplicate
  and outstanding-owner matching, before processing any completion. A
  synchronous completion observed while the submitter is in `Submitting` is
  retained in `EarlyReady` and applied only after acceptance is published.
- Checked stop quiesces graph and service work, unregisters buffers in reverse
  order, shuts backends down in reverse order, retains the first error, and
  retries unresolved work only. Existing destruction fallback and two-Runtime
  isolation tests pass unchanged through the adapter.

## Deterministic CI repair

- GitHub Actions run `31003660099` at head
  `1d1c3a5830656331fa61dfb3877c70db601d2bdf` completed with one causal
  failure in Windows Debug:
  `TraceNoAlloc.NativeHalV2FinalizedStartFramesAndStopDoNotAllocate` observed
  two allocations. The `simcore_all` and `m17_hal_v2_compatibility` CTest
  failures were duplicate invocations of that test, and the Windows
  RelWithDebInfo cancellation was cascading fail-fast behavior.
- Classification: test defect, high confidence. On non-Linux platforms,
  `NativeThread::start()` constructs `std::thread`; this configuration starts
  one executor worker and one device-service lane. The test placed
  `Runtime::start()` under the allocation guard and therefore counted the two
  implementation-owned startup-thread allocations on MSVC. The memory
  contract explicitly excludes OS thread stacks and implementation-owned
  thread state, and the M17-01 allocation-free boundary begins after
  successful start.
- Repair: renamed the focused test to
  `TraceNoAlloc.NativeHalV2FramesAndStopDoNotAllocateAfterStart` and moved only
  successful startup before the allocation guard. All 64 native HAL frames
  and checked stop remain inside the guard, preserving the contracted
  no-allocation assertion without changing runtime behavior or a protected
  interface.
- Focused repair command:
  `cmake --build build/agent-full --parallel 2 && ./build/agent-full/tests/simcore_tests --gtest_filter='TraceNoAlloc.NativeHalV2FramesAndStopDoNotAllocateAfterStart' && ctest --test-dir build/agent-full --output-on-failure -R '^m17_hal_v2_compatibility$'`
  - Exit 0. The direct focused test passed 1/1 and the M17 CTest process
    passed 1/1 on the available Linux host.
- Full repair verification: `./scripts/agent-verify.sh full`
  - Exit 0. Contract, documentation, release, and frozen C ABI gates passed;
    quick CTest passed 19/19 and strict experimental CTest passed 23/23,
    including `simcore_all` and `m17_hal_v2_compatibility`.
  - Retained log:
    `docs/evidence/local/verify-full-20260805T120938Z.log`.
- The Windows Debug job was not rerun because this repair was not committed or
  pushed. Mandatory post-repair GitHub CI remains an external gate.
