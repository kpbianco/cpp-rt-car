## Ownership, identity, accounting, and call-path evidence

- Extension tables and snapshots are copied into one individually allocated,
  Runtime-owned `HeterogeneousMemoryState` per backend. The `unique_ptr`
  preserves the callback table and snapshot address while configuring vectors
  grow; Runtime handles include the Runtime-local backend owner.
- `DeviceManager` owns one fixed `NativeMemoryState` per canonical memory
  object. A legacy object holds the old core token. A heterogeneous object
  holds the complete versioned token and an explicit uncertain-ownership bit.
- Register order is deterministic. Before entering `register_memory`, Runtime
  marks ownership uncertain. Reverse unregister retains the descriptor and
  token until success, continues independent cleanup, preserves the first
  error, and prevents backend shutdown while ownership remains unresolved.
- A coherent opaque submission test observes exactly one translated backend
  token (`0x2001` in the fixture), with the requested 8-byte offset, 16-byte
  range, and read access. A flush-required object returns `device_error` with
  zero backend submit calls.
- Conditional graph identity hashes every active domain, node, directed link,
  timestamp/correlation-capability, completion-domain, and explicit
  registration semantic field. Tests prove sensitivity to domain,
  byte-count, ownership, access, and opaque bytes, plus equality across
  distinct host pointer addresses.
- Two otherwise identical plans with opaque payload declarations of 64 and
  128 bytes have identical planned and device-control bytes; their external
  buffer row changes from 128 to 192 total declared bytes. Device control is
  exact, the external mixed row is `declared_only`, and planned bytes remain
  the exact sum of runtime control, executor control, device control, phase
  scratch, task scratch, and trace storage.
- The no-allocation fixture places successful start before the allocation
  guard and verifies frozen inspectors, device health, and checked stop under
  the guard. Startup thread construction remains outside the contracted
  steady-state boundary.

## Independent system-risk review and repair

The uncommitted full diff, active batch, public/package interfaces, architecture,
device, memory, determinism, observability, release, security, threat, and
real-time claim contracts were reviewed for correctness, concurrency, lifetime,
resource, migration, compatibility, security, licensing, recovery, and test
failure modes. No material implementation defect requiring an in-scope runtime
repair was found.

One medium-severity evidence gap was found: the retained evidence claimed that
timestamp-correlation requests reject an active frame, but no behavioral test
held a frame callback in flight and proved that the backend correlation callback
was not entered. `HeterogeneousMemory.CorrelationRejectsAnActiveFrameWithoutEnteringTheBackend`
now uses deterministic latches to hold an active callback, requires
`invalid_state`, verifies transactional zero output and zero backend correlation
calls, then releases the frame and proves ordinary step and checked stop
recovery. The focused selection passes with 21 tests after this repair. The
review added no runtime feature, lane, status, ABI, package, schema, or claim.
